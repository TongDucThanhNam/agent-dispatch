For code navigation, use `rg` for filenames and literal text, `ast-grep` for syntax structure, and LSP/compiler tools for resolved references and types. Scope searches before broadening; outline large unfamiliar files before reading unless the relevant symbol is already located. Respect ignore files. Dry-run and inspect `ast-grep` rewrites before applying them.

Prefer equivalent compact idioms over aliases when the complete command is shorter: `sed -n '249,408p' file` for a requested line range, `test -e`, `&&`/`||`, and `NAME=value command`. Preserve output, quoting, encoding and failure semantics; do not cap output, omit diagnostics or disable capabilities for token savings. On Windows, invoke Git Bash explicitly for POSIX commands (`& 'C:/Program Files/Git/bin/bash.exe' -c '...'`); keep direct Git/`rg`/`ast-grep`/Bun calls direct and Windows-specific or destructive filesystem operations in PowerShell. Set `workdir` and use relative paths in commands rather than repeating absolute prefixes.

Return command output as plain text: in `exec` scripts print `r.output` (prefixed with `exit_code` when nonzero or relevant) per command, not the whole result object; `text(result)` JSON-escapes every newline and quote. Script output beyond its budget is truncated in the middle, so batch several targeted ranges rather than several whole files, and outline a document's headings before reading it whole. Render PowerShell objects with `ConvertTo-Json -Compress -Depth N`, `ConvertTo-Csv` or `-ExpandProperty`, not default or `Format-*` tables/lists that pad and wrap at console width. Verify an edit with `git diff -- <path>` instead of re-reading the file.

Images cost the most context: view screenshots at the default `high` detail and pass `original` to `view_image`/`image()` only when exact pixels or small text matter. Prefer element or region screenshots over full-page ones, and do not re-view an unchanged image or re-read unchanged file content already in context.
