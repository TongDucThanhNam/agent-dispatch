## Claude Code worker
- Requires the native `claude` executable (Claude Code 2.1.259 or newer). On Windows the launcher resolves `claude.exe`, not a PowerShell function or `.cmd` wrapper. Advanced `--config` may set `claudeExe` and `claudeHome` (`CLAUDE_CONFIG_DIR` by default).
- Without `--model`, Claude uses its existing settings/account default. With `--model`, accept a single model ID or alias (`sonnet`, `opus`, `haiku`, `best`, `fable`), optionally with `[1m]`. The actual model is verified from `system/init`, saved and pinned for exact-session resumes. `opusplan` is not supported because it deliberately switches models. `{{CLI}} models --worker claude` lists aliases and advisory settings, not account availability.
- Optional `--effort low|medium|high|xhigh|max` is model-dependent. An explicit effort overrides inherited effort settings for this worker only. No global settings are changed.
- `--mode yolo` uses `bypassPermissions` for authorized unattended work. `--mode plan` uses Claude's plan permission mode. Discovery defaults to yolo so read-only commands and tests can run; its no-edit rule is enforced by the brief and the working-tree guard, not a filesystem sandbox. Permission requests requiring a person are denied with `--permission-prompts none`.
- Uses normal Claude authentication and loads project instructions, settings, hooks, plugins and MCP servers just like the existing CLI. It does not use `--bare` (which ignores subscription credentials). Provider routing stays in Claude's settings/environment; do not pass `--provider` to select a Claude backend.
- The prompt goes through stdin, not the command line. Raw events and a compatible telemetry projection are saved inside the run directory. Partial and final assistant records are deduplicated; aggregate result usage is not added to per-request totals. Subagent records are isolated from the main session's model check and included in session exports.
- `resume` passes the exact saved `--resume` session UUID, never `--continue`. Nested non-interactive Claude sessions still persist; the launcher preserves Claude's session markers and credentials. Quota/auth failures are blockers, not permission to switch accounts or retry automatically. The worker uses the selected account's billing/quota.
