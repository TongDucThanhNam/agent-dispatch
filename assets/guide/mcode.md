## MiniMax Code Desktop worker
- `--worker mcode` uses **MiniMax Code Desktop**, its runtime and visible sessions: no standalone `mcode exec`/CLI install, credential copies, BYOK switch or second desktop-DB owner.
- Windows only. Desktop 3.1.14 bridge/setup pass; live smoke quota-blocked (historical full smoke: 3.0.74). After app closes/restarts, `{{CLI}} mcode setup` attaches its valid bridge or starts a closed app with the opt-in loopback diagnostic sidecar. If open without a bridge, close normally first; no forced restart. `mcode status` is read-only; unsupported contracts fail without fallback.
- Candidate `dispatch-worker`: `bun run setup:mcode-worker` (3.1.14), opt in via advanced-config `mcodeAgent`. Setup/preflight verified, not live acceptance/full tool catalog; quota keeps default `mavis`. Its seven-tool selector and limits: `docs/mcode-worker-context.md`.
- Paths: EXE `%LOCALAPPDATA%/Programs/MiniMax Code/MiniMax Code.exe`; manifest `~/.minimax/run/agent-dispatch-desktop.json`. Override via `MCODE_DESKTOP_EXE` / `MCODE_DESKTOP_MANIFEST` or advanced-config `mcodeExe` / `mcodeManifest`. Never paste/commit the manifest's ephemeral startup token or include it in briefs/exports.
- Requires the desktop's managed **Token Plan** model source and normal desktop sign-in. `{{CLI}} models --worker mcode` reads the app's real model roster. Omit `--model` to pin its selected model, or use `--model minimax/<model>[#variant]`. Optional `--effort default|low|medium|high|xhigh|max` is validated against that model's roster. Provider/model/variant/effort are session-scoped and verified before delivery and after completion. Global settings stay unchanged. No particular promotion or billing eligibility is promised by the bridge.
- `--mode yolo` authorizes unattended work through the desktop's normal permissions. Only permission requests belonging to this dispatched session and agent receive **AllowOnce** replies; never AllowAlways or global bypass changes. Native plan/goal sessions and `--mode plan` are currently rejected, not silently translated. Discovery uses the standard read-only brief and worktree guard, not a filesystem sandbox. Do not use this worker when a hard read-only sandbox is required.
- Uses the normal two-stage discovery → orchestrator planning → execution flow. New execution runs get new visible desktop sessions; exact-session `resume` creates a new turn in the saved `mvs_...` session, never the latest workspace session. A busy, archived, foreign-project, or differently configured session is not taken over.
- Questions/plan reviews requiring a person become a clear blocker; do not fabricate answers. Resolve them in the recorded desktop session before resuming. Account/quota failures are blockers, not permission to retry, switch providers or consume resets.
- `stop` aborts the exact dispatched **turn**, verifies release, and leaves the desktop app and other sessions running. If abort or transport ownership is uncertain, the lock remains held; inspect the desktop session before recovery. Disconnecting a stream alone is not proof of cancellation.
- Raw native events and compatible SQLite telemetry stay in each run directory, never the desktop database. Text/tool chunks are deduplicated; final messages replace streamed content. Missing usage remains unknown. Only a native terminal marker plus finished session/model verification can produce success.
- `{{CLI}} desktop <ref>` identifies the already-visible session by title/ID after the turn finishes. Continue from one client at a time.
